Prior times likelihood

The posterior weighs every candidate rate by prior and data

lp = log_prior(grid) + log_lik(grid, counts, km)
w = np.exp(lp - lp.max())
w = w / w.sum()   # posterior weights on the grid
  • Work on the log scale: products of many probabilities underflow.
  • Subtract the maximum before exponentiating.
  • The normalising constant is the sum of the weights.

Write p(rate | data) ∝ p(rate) × p(data | rate) on the board and point at each term in the code. The prior is a lognormal centred on 0.10 bursts per km-year with a log-scale spread of 1: Shabib's "about one burst per 10 km a year". Session 2 tests that prior.

Why we need a sampler

A grid works for one rate and fails for 140

10^280
grid points for 140 rates at 100 points each
  • The grid grows exponentially with the number of unknowns.
  • Almost all of its points have negligible posterior weight.
  • A sampler spends its effort where the weight is: session 3.

Lab 1.1 task 5 computes the exponent. Ask for a guess before showing it. The point is not the number but the idea of "typical set": in high dimension the posterior mass sits in a thin shell, which is why Hamiltonian Monte Carlo follows the geometry instead of guessing.

The evidence LO1 asks for

Every prior in the notebook carries one sentence of reason

α ~ Normal(log 0.1, 1)

Centred on the engineers' "one burst per 10 km a year"; 73% of simulated network totals within their plausible range.

β age ~ Normal(0, 0.5)

Median rate ratio 1.0 per 10 years, 95th percentile 2.3: "might double, never five times".

A reason quotes a number or a statement. "Weakly informative" alone is a label, not a reason.

Lab 1.2 task 5 asks for the age prior. Some will pick Normal(0.3, 0.2) from what they expect; that is defensible if they write why, but it uses a belief about the direction that the engineers did not state. Discuss both.

A working definition

Weakly informative: rules out the impossible, stays open on the plausible

Too vague

Puts weight on rates no pipe ever had. Harms small districts.

Weakly informative

Spans every rate an engineer would accept, and little beyond.

Informative

Carries a measurement: an audit, an earlier study. Day 2 uses one for reporting.

Point forward: Lab 2.4 uses an informative prior on the share of bursts reported, from a 2024 audit, because the data cannot identify it. That prior must be defended by the audit, not by convenience.

Session 3

Fitting with Hamiltonian Monte Carlo

  • Explain how Hamiltonian Monte Carlo uses the gradient of the log posterior
  • Write a Poisson model with an offset in a probabilistic programming language
  • Report rate ratios with posterior intervals
03
Monte Carlo

A pile of posterior draws answers any question you can compute

  • A median, an interval, a probability: functions of the draws.
  • A derived quantity, such as next year's bursts in D017, is computed draw by draw.
  • The decision on Day 4 is a cost computed in every draw, then averaged.
mu = np.exp(a + b @ X[j]) * km[j]   # one value per draw
np.quantile(mu, [0.5, 0.05, 0.95])

Stress the habit: never summarise early. Compute the quantity in each draw, then summarise. Averaging the rate first and then computing costs gives the wrong expected cost when the cost is not linear (Day 4).

Hamiltonian Monte Carlo

HMC rolls a particle across the posterior using its gradient

Position

The current values of all parameters.

Momentum

A random push, drawn fresh at each iteration.

Gradient

The slope of the log posterior steers the path towards high density.

The path is followed in small leapfrog steps; the end point is accepted or rejected so that the draws come from the posterior.

The physics analogy: a frictionless puck on a surface whose height is minus the log posterior. Momentum carries it far in one iteration, which is why HMC explores many dimensions where random-walk samplers stall. The gradient comes from automatic differentiation (JAX in NumPyro, Stan's own in Stan).

Sources: Betancourt (2017), A Conceptual Introduction to Hamiltonian Monte Carlo.

The No-U-Turn sampler

NUTS chooses the path length; warm-up chooses the step size

SettingWho sets itWhat goes wrong
Path lengthNUTS: doubles the path until it turns backPaths that hit the maximum tree depth: slow
Step sizeWarm-up: tuned to a target acceptance rateToo large for a curved region: divergences
Mass matrixWarm-up: the scale of each parameterVery different scales: slow mixing

Warm-up draws are discarded: they are tuning, not samples. NumPyro's default target acceptance is 0.8; raising it shrinks the step size, which sometimes hides a geometry problem without fixing it (Lab 2.3 stretch).

Lab 1.3, task 1

The model is the generative story, written as code

def pooled_model(d, log_km, X, y=None):
    alpha = numpyro.sample("alpha", dist.Normal(np.log(0.10), 1.0))
    beta = numpyro.sample("beta", dist.Normal(0.0, 0.5).expand([4]).to_event(1))
    eta = alpha + X @ beta                      # log rate per district
    numpyro.sample("y", dist.Poisson(jnp.exp(log_km + eta[d])), obs=y)

The same function simulates data when y is missing and conditions on it when y is given.

Walk the lines in order of the story: prior on the base rate, prior on the effects, the log rate, the exposure as an offset, the count. The other probabilistic programming languages (Stan, PyMC, brms) write the same five lines in their own syntax; the tool slot on the next slide lists them as interchangeable.

Validity failures: chains that disagree, divergences, low E-BFMI. Efficiency warnings: capped trees, a long run time. An efficiency warning becomes a validity problem only when it leaves too few effective draws, which the ESS shows.

Looking at chains

Rank plots show chains that disagree better than trace plots do

  • Rank all draws of a parameter together, then plot each chain's ranks as a histogram.
  • Chains from the same distribution: flat, similar histograms.
  • A chain stuck high or low: a histogram piled at one end.
pc = az.plot_rank(fits["fit_C"], var_names=["alpha", "tau"])
pc.savefig("artifacts/rank_fit_C.png")

Show the two saved rank plots from a participant's run. In fit C, chain 4's ranks pile at the top for alpha. In ArviZ 1.x plotting functions return a PlotCollection; savefig writes it.

When approximate inference suffices

An approximation is fine when the posterior is simple and the question is its centre

90% interval of βNUTSVariational (AutoNormal)
Age per 10 years0.265 to 0.3340.253 to 0.326
Asbestos cement0.533 to 0.6990.551 to 0.698

Five parameters and 700 counts: close enough for a rate ratio. For 140 district effects, skewed spreads and tail decisions, sample.

From the Lab 1.4 stretch, quick run. Variational inference fits a simple distribution to the posterior; it tends to understate uncertainty and cannot represent a funnel. Use it for a quick first look, for very large data, or inside a loop where speed matters; check it against a sampler at least once.

Checkpoint

Which fit to send back

A fit reports R-hat 1.003, bulk ESS 2,100, no divergences, and 40% of draws at the maximum tree depth. Another reports no divergences and R-hat 1.21. Which do you send back?

The first, because 40% of trees are capped
Neither, because neither has divergences
Both, because each has a warning
The second, because its chains disagree
Why. An R-hat of 1.21 means the chains explore different distributions; capped trees in the first fit cost time but its chains mixed.

Answer: D. This is the shape of the supervised check: read diagnostics without AI and decide. Ask the room what they would request from the second fit's author: more warm-up and four fresh starts, then the four checks again.
